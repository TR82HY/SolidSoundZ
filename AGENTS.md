# AGENTS.md

SolidSoundZ: a Next.js 14 (App Router) SoundCloud-style music platform. Production: https://solidsoundz.vercel.app (Vercel project `swnelson26-4729/solidsoundz`).

> `README.md` describes an earlier plan (Hetzner/R2/Clerk-only/$5.99 polsia.io). The live app has since moved to Vercel + Neon + Vercel Blob with native auth as primary — this file reflects current reality; trust this over the README.

## Build & verify

- `npm run build` is the **only real verification gate** — it runs `scripts/prisma-provider.mjs` (switches the Prisma datasource provider based on `DATABASE_URL`), `prisma generate`, `prisma db push`, then `next build` (which also typechecks and lints). There is no separate test suite or lint script.
- For a quick check without a full build, use `tsc --noEmit`. It checks against the currently generated Prisma provider, so keep provider-specific query options conditional (see Case sensitivity below).
- After touching `prisma/schema.prisma`, always run `prisma generate` before typechecking, or Prisma Client types will be stale.
- Never add `@unique` to a field on a model that already has production rows without also confirming no duplicates — `prisma db push` will refuse (data-loss guard) and require `--accept-data-loss`. Prefer a plain `@@index` over a new unique constraint on existing tables.

### Windows terminal gotcha

This repo is developed from a Windows PowerShell terminal that intermittently loses command resolution mid-session — even builtins like `Get-Command`/`Get-Location`/`cmd.exe`/the `&` call operator can start throwing `CommandNotFoundException` for no environmental reason. When that happens, invoking `node.exe` by its full path still works. Prefer this form for any CLI (npx, prisma, vercel):

```powershell
& "C:\Program Files\nodejs\node.exe" "C:\Program Files\nodejs\node_modules\npm\bin\npx-cli.js" <args>
```

Never run `next dev` in a terminal you plan to reuse for other commands — start it in a dedicated terminal.

VS Code's **Terminal > Run Task** provides `Build SolidSoundZ`, `Run SolidSoundZ locally` (development), and `Preview SolidSoundZ build` (after a successful build) via `.vscode/tasks.json`. These use `npm.cmd`; each server runs in its own terminal at `http://127.0.0.1:3000`. Run only one server task at a time. This is also a supported way to run the app when the agent's PowerShell tool cannot start on Windows.

## Architecture

- Pages live under `app/(site)/` and share one layout: `Nav` + `PlayerProvider` + `PlayerBar` (see `app/(site)/layout.tsx`). `app/embed/[id]` is a bare iframe player, intentionally excluded from auth middleware.
- Global playback state lives entirely in `components/player/PlayerProvider.tsx` (`usePlayer()` / `usePlayerTime()` context). It owns the queue, persists it to `localStorage` (`ssz-queue`) so playback survives navigation, and switches between an `<audio>` element and the hidden `SoundCloudWidget` iframe per-track (`soundCloudPlayback` flag on `TrackCardData`). Don't build parallel playback state — extend this provider.
- Saved playback queues are validated and reopen paused, including their position and volume. Keep one native audio element and explicitly reload its source for retries; obsolete play/next requests must not restart stopped audio or repopulate a cleared queue. The header has no duplicate Stop; the player owns Stop/rewind, volume/mute, source information and Media Session controls. Native uploads play without extra transcoding; do not advertise an invented SoundCloud bitrate or lossless setting.
- Player loading, error and notice messages belong in full-width rows below the controls, never inside the desktop-only track details. Verify failure states at mobile and desktop widths as well as successful playback; retry text must not expand the fixed player over the page or disappear on phones.
- SoundCloud playback time comes from widget progress/seek events, never the native audio polling loop. Volume changes must not rebind the widget's `READY` handler (the SDK immediately replays it for initialized widgets, which otherwise restarts paused audio). Load the SDK before navigating the initially blank iframe, or server-rendered embeds can emit `READY` before its listener exists. Buffer controls until readiness, give each source a fresh iframe, and dispose SDK bindings before detaching that iframe. The transport needs `autoplay; encrypted-media` permissions for SoundCloud's supported media paths.
- `EmbedPlayer` uses that same transport for SoundCloud-backed tracks with `autoPlay={false}`; never feed their placeholder `audioUrl` to a native `<audio>` element. Embeds fill their iframe viewport and stay paused until the listener presses Play; native-file embeds keep their existing audio transport. Copied embed markup in `ShareMenu` must also allow `autoplay; encrypted-media`, since an inner iframe cannot grant a media capability denied by its outer embed.
- Studio (mix/master) is isolated under `components/studio/Studio.tsx` + `lib/studioChain.ts` + `lib/loudness.ts`.
- Studio loads commit only after a successful decode, and obsolete local/library/generation loads must not replace the latest selection. Processing jobs are exclusive and invalidate old analysis when settings change. A/B matching attenuates the louder preview instead of boosting the quieter one; preview matching, bypass, and monitor volume never alter export settings. Saved settings are validated before touching audio parameters.
- Studio controls pair visible beginner hints with associated labels and accessible descriptions; do not make guidance hover-only. Keep per-control resets, the quick-start guide, and the distinction between local downloads and public publishing.
- `lib/` is organized by concern, not by feature: `account.ts` (native sessions), `artist.ts` (`getArtist()` — the identity resolver, see Auth below), `queries.ts` (all public track/feed reads), `storage.ts`/`r2.ts` (file storage), `soundcloud.ts` (import/OAuth helpers), `studioChain.ts`/`loudness.ts` (audio DSP).

## Auth: two systems, one is primary

- **Primary**: native email/password sessions (`lib/account.ts`, httpOnly cookie) plus SoundCloud OAuth (`app/api/soundcloud/*`, PKCE flow). `getArtist()` in `lib/artist.ts` and `currentAccount()` in `lib/account.ts` are the only correct ways to resolve "who is signed in" in a route or page.
- Sign-out revokes the current native session and clears this browser's SoundCloud access token and pending OAuth cookies; it does not unlink the artist's SoundCloud ID or delete their catalog. Restoration preserves an existing native account, returns `{ user: null }` for no saved login/expired authorization, and reports upstream or database failures separately. Client auth/activity reads must be abortable so stale responses cannot overwrite newer state or a completed sign-out.
- **Legacy/optional**: Clerk, gated behind `clerkConfigured()` (`ENABLE_CLERK_MIDDLEWARE === 'true'` + valid keys). `middleware.ts` only mounts Clerk's `authMiddleware` when that's true; otherwise it's a no-op passthrough.
- **Pitfall (previously a real bug):** never call Clerk's `auth()`/`currentUser()` directly in a route — if Clerk middleware isn't mounted (the common case in production), `auth()` throws or silently fails. `/api/checkout` did this and Pro subscriptions were broken until fixed. Always go through `getArtist()`.
- Profile management lives at `/settings` and `/api/artists/me`. Edits require the signed-in profile ID and preserve its slug; deletion additionally requires an exact-name confirmation and the current password for password-backed accounts. Delete dependent catalog/activity data and sessions in one transaction, stop source sync, and retain only an opaque `DeletedProfile` ID to prevent legacy/dev auto-provisioning from resurrecting it. Public profile reads must never create or re-claim accounts.
- SoundCloud OAuth is bound to its initiating account with `soundcloud_oauth_account`; sign-out clears this with the other OAuth cookies. Resolve linked accounts by stable SoundCloud ID, reject ambiguous links, and never merge users by their display names. Reconnect preserves edited profile fields and uses the same leased public-catalog sync instead of a competing import.
- The site owner's verified `User.soundCloudId` must match server-only `SITE_OWNER_SOUNDCLOUD_ID` for `isSiteAdmin()`. `hasProAccess()` grants that account Pro without changing its stored billing plan; checkout rejects Admin purchases. The Admin badge is derived on the server, never from a name, form value or local storage. Existing generation usage limits still apply.

## Data conventions

- Anonymous listener identity (likes/follows/reposts/play-events from signed-out visitors) is a salted httpOnly cookie from `lib/listener.ts`, distinct from artist accounts.
- **Self-notification pattern**: when adding any action that notifies a track/profile owner (like, repost, comment, follow), check the actor isn't the owner before calling `db.notification.create` — otherwise artists spam their own notification feed acting on their own content. See `app/api/tracks/[id]/{like,repost,comments}/route.ts` for the pattern.
- Track visibility (`published`, `publishedAt`, `scheduledFor`) is only correct when read through `lib/queries.ts` (`listTracks`, `trendingTracks`, `getTrackCard`, `relatedTracks`, `feedTracks`). These call `publishDueTracks()` first, a self-healing sweep that flips due-scheduled drafts live (no cron job exists — the sweep runs opportunistically on public reads instead). Querying `db.track` directly for a public listing will skip both the visibility filter and the sweep — `feedTracks` (Stream) was missing the `published: true` filter entirely until this was caught, leaking followed artists' private drafts.
- Stream reposts are selected by `Repost.listener` matching followed artist IDs, not by the reposted track's owner. Merge uploads and reposts by activity time, then deduplicate by track ID so a recent repost can surface an older track. Both sources must require published tracks from claimed profiles.
- Public playlist cards also go through `listTracks`, then are ordered by their saved playlist positions. Do not rebuild track cards directly from playlist relations: that skips claimed-profile visibility, scheduled publication, storage URL handling, and shared waveform parsing.
- Automatic SoundCloud refresh is opt-in per artist through `SoundCloudSync`. Public reads and the visible-page `SoundCloudRefresh` poll check the five-minute freshness window; idle sites catch up on the next visit, not through a continuous cron. Official API access/refresh tokens are encrypted with the server's client secret and reused through `SoundCloudApiSession`, with database leases preventing duplicate refreshes. Never use downloaded/redacted credentials or website client IDs as substitutes for the configured API app.
- Source-refresh timestamps pass a server `referenceTime` to `RelativeTime`; elapsed time then uses the browser's monotonic clock. Do not use an untrusted device clock to label a just-completed server sync as stale. Initialize an externally enabled connection's first `nextSyncAt` to an already-due time, not the operator machine's clock.
- SoundCloud sync matches stable track IDs (current URNs and legacy numeric IDs) or exact source URLs, only creates public fully playable releases, and never deletes tracks or resets publication on reconnect. Original uploads and Apple-approved metadata are preserved. Failed/missing counters retain their previous values; quiet-mode source stats/comments are hidden rather than claimed as zero. Source plays/likes/reposts/comments and followers remain separate from SolidSoundZ activity, with timestamps and visible retry status.
- Music platform links live in `Track.appleMusicUrl` and `Track.spotifyUrl`. `MusicPlatformLinks` pairs both buttons on cards, release pages and featured releases; missing links explicitly search by title and artist instead of pretending to be verified matches. Owner edits validate official song URLs through `lib/musicLinks.ts`. Catalog refreshes preserve saved links, audio, engagement, publication and upload dates; never substitute previews for full tracks or guess different versions from title alone.
- Client-rendered relative dates use `RelativeTime`: SSR and the first client render share a UTC calendar date, then relative time updates after hydration. Do not render `Date.now()`-based labels directly in server-rendered client components.
- Track/profile sharing, playlist selection, and the playback queue share `ActionPopover` for viewport-aware positioning, keyboard dismissal, and focus return. Show actionable request errors, prevent duplicate submissions, and never report a playlist/comment save before validating the response. Playlist creation with an initial track is one nested database write.
- File storage falls back in this order, transparently, via `lib/storage.ts`: Vercel Blob (`blobConfigured()`) → Cloudflare R2 (`r2Configured()`) → local `./storage` folder served through `/api/audio/[...key]`. Don't assume one backend; check `saveFile()`'s return value (`null` means "served locally/via R2", a string means a public Blob URL).
- Prisma schema is portable on purpose (no `Json`/enum types) because `scripts/prisma-provider.mjs` swaps `datasource.provider` between `sqlite` (local `dev.db`) and `postgresql` (Neon) based on whether `DATABASE_URL` starts with `file:` or `postgres`. Don't hand-edit the `datasource` block.
- **Case sensitivity**: user-text searches must keep `mode: 'insensitive'` on Postgres, where matching is case-sensitive by default. SQLite's default `LIKE` matching is case-insensitive for ASCII, but its Prisma client rejects `mode` both in types and at runtime. The shared `textFilter` in `app/(site)/search/page.tsx` adds `mode` only for `postgres://` or `postgresql://` database URLs, matching `scripts/prisma-provider.mjs`. Use this provider-aware pattern for user-typed `contains`/`startsWith` filters; do not remove production case-insensitive matching or pass `mode` unconditionally.
- **Literal backslashes in search**: Postgres treats backslashes as `LIKE` escapes. The shared search filter doubles them on Postgres so displayed names such as `TR/\2HY` match literally; SQLite keeps them unchanged. Keep this escaping in both track and artist filters, including the lowercased slug filter, without changing the displayed query.

## Other conventions

- Site typography uses `next/font` in the root layout so Space Grotesk, Bebas Neue, and DM Mono are served with the app. Keep font variables in the global styles; a remote CSS `@import` after Tailwind rules is ignored by browsers.
- Branding: use `components/BrandLogo.tsx` for brand links in the navigation, promo page, and embed player. Its font-independent SVG wordmark and orbital-Z mark live in `public/brand/`; root metadata uses the same mark as the browser icon. Only the DJ record behind the fixed Z rotates (8-second loop). A media-selected static SVG variant guarantees reduced motion even when a browser treats animated SVG images differently from SVG documents; keep static and animated geometry in sync. The wordmark is designed for dark backgrounds; the compact mark includes its own dark background. Header search has its own row, and primary navigation uses the scrollable row below `xl`, so the logo and actions stay readable at narrow widths.
- SEO: `app/sitemap.ts`, `app/robots.ts`, OG/Twitter player cards on `/t/[id]`. Sharing UI: `components/ShareMenu.tsx` (tracks), `components/ProfileShareButton.tsx` (artist profiles).
- Autoplay continuation goes through `/api/next`.
- Monetization: Stripe Connect Express for artist payouts (`/api/stripe/connect`, `/api/stripe/dashboard`), one-off fan contributions (`/api/contributions`, `Contribution` model), and a Pro subscription (`/api/checkout` + `/api/stripe/webhook`). All gated on `process.env.STRIPE_SECRET_KEY` being a real (non-placeholder) key.
